# Audit

Deep review of the unity-sync codebase: a Go CLI that mirrors the assets owned on the
Unity Asset Store into a local library, downloading only what changed since the last run.
Reviews everything by default. If the user provides a scope (e.g. "the syncer", "cache and
lockfile", "the store client"), narrow to those areas.

Scope: $ARGUMENTS

## Step 1: Determine scope

- **No arguments:** review every `.go` file outside the exclusions below, plus `install.sh`,
  everything under `.github/`, `config.example.toml`, and `unity-sync.example.toml`. The
  root-level `main.go`, `main_test.go`, `audit_test.go`, and `install_test.go` are easy to
  forget; they are in scope.
- **With scope:** interpret the user's wording to identify which `internal/` packages or
  root files to review. When in doubt, include more rather than less.

Do not review the following. Where an exclusion is produced by code in this repo, review
the producer instead.

- `testdata/store/*.json`: generated by `go run ./cmd/scrubfixtures` from raw captures
  that are never committed. Review the producer, `internal/fixtures/scrub.go` and
  `cmd/scrubfixtures/main.go`, instead.
- `testdata/store/package_header_sample.bin`: the leading kilobyte of a real downloaded
  package, captured by hand and not produced by `scrubfixtures`, which only reads and
  writes `*.json`. It is a gzip header whose FEXTRA descriptor carries the store's own
  product and publisher metadata (ids, title, version, category, Unity version) and nothing
  scoped to an account; `internal/fixtures/guard_test.go` walks it as bytes like every
  other fixture. There is no producer to review in its place.
- `internal/store/testdata/search_query.graphql`: a golden copy of `store.SearchDocument`,
  pinned by `TestQueryDocumentMatchesItsGoldenCopy`. Review the document in
  `internal/store/store.go`; the golden only mirrors it.
- `go.sum`: generated by the toolchain.
- Anything matched by `.gitignore`: `config.toml`, `session.curl`, `*.curl`, `cookies.txt`,
  `captures/`, `unity-sync.toml`, `unity-sync.lock.json`, and the built `/unity-sync`
  binary. These are account data and local state and are never committed.

## Step 2: Run baseline checks

Run these first. Proceed with the audit either way, since area findings may explain a
failure or reveal it as pre-existing. Report any failure as Tier 1, ahead of new findings.
Do not re-decide in prose what these commands decide: if the formatter is clean, formatting
is not a finding.

```bash
go build ./...
gofmt -l .           # any output is a failure; the file list is the failure
go vet ./...
go test -race ./...  # what CI runs on ubuntu
# the fuzz step CI runs; about 45 seconds between them
go test ./internal/session/ -run=XXX -fuzz=FuzzLZ4Block -fuzztime=20s
go test ./internal/session/ -run=XXX -fuzz=FuzzDecodeMozLZ4 -fuzztime=20s
```

CI's `cross` job also runs `go build ./...` and `go test ./...` on `windows-latest` and
`macos-latest`, which you cannot reproduce here. The release ships binaries for both, so
the path handling behind the lockfile's `cachePath`, the case-insensitive filesystems
`cache.SameFile` exists for, the Gecko profile roots, and the rename that replaces a
running executable are all shipped code this machine never executes. Reason a portability
finding in those places; do not assume the green Linux run covers them.

`.github/workflows/ci.yml` also carries two shell guards that decide their question
mechanically: every `uses:` under `.github/` is pinned to a 40-character SHA, and no
compiled binary is tracked. Neither is reproduced above; neither is re-decided in prose
below. Review the guards themselves as code (Step 3, distribution area).

There is no Makefile, task runner, or lint configuration; the `go` toolchain is the whole
baseline. `go run ./cmd/scrubfixtures` is deliberately left out of this block: it needs raw
captures that are git-excluded, so it cannot run in a clean checkout.

The suite is fully offline and needs no session: every test runs against `httptest` servers
and the committed, scrubbed fixtures in `testdata/store/`. It takes a few seconds. A green
run therefore says nothing about live store behaviour; `docs/design.md` is the only record
of that, and it is measured, not tested. There is no coverage gate. The one test that reads
a real artefact, `TestDecodesARealSessionStore` (`internal/session/browser_test.go`),
skips unless `UNITY_SYNC_REAL_SESSIONSTORE` names a `recovery.jsonlz4`; the two fuzz
targets in `internal/session/fuzz_test.go` are what exercise the mozlz4 decoder on input
the suite did not encode itself. Both example files are fed through `Load` by
`internal/config/config_test.go` and `internal/manifest/manifest_test.go` (via
`fixtures.UncommentSettings`), so an example key the structs no longer decode is a test
failure, not a review finding. Each package with pinned failure models keeps them in its
own `audit_test.go`, apart from `<pkg>_test.go`; a change that breaks one of those is
breaking a documented invariant, not hitting a flaky test.

## Step 3: Dispatch review sub-agents

Use `feature-dev:code-reviewer` sub-agents to review the scoped files. Split by area so
agents run in parallel:

- **Session sources**: `internal/session/` (`session.go`, `browser.go`, `mozlz4.go`,
  `session_test.go`, `browser_test.go`, `audit_test.go`, `fuzz_test.go`). A leaf package
  that imports nothing else in the tree. It turns one of three saved-session formats into
  the Cookie header, decides which format a path is by reading it, and decodes Gecko's
  compressed session store itself. What goes wrong here: a decoder that trusts a length
  that came off disk; a host filter that lets a cookie from an unrelated site through; a
  `cookies.txt` parser that reads `#HttpOnly_` as a comment and so drops exactly the
  credential; a curl-paste unquoter that handles one shell's quoting and drops the cookie
  from the others (POSIX, ANSI-C `$'…'`, and the Windows cmd `^"` form); a `-b` value
  holding no `=` taken as a credential when curl reads it as a jar filename; a profile
  ranking that lets `Default=1` or a resting store outrank the profile the running browser
  uses; a container tab's `LS` outranking the default context's; a diagnostic that quotes
  what it just read.
- **Store client and retry**: `internal/store/` (`store.go`, `store_test.go`,
  `audit_test.go`, `export_test.go`), `internal/retry/`. Turns a Cookie header into
  authenticated requests, owns the pinned GraphQL document and the response-level download
  guards, and decides what each failure means. What goes wrong here: a guard that reads the
  body before the response is judged; a status classified retryable that a second attempt
  cannot fix; a first request (the bootstrap) that retries on different terms from every
  later one; a rejected response whose drain is unbounded; a required header that silently
  stops being sent because a permissive server still answers 200.
- **Cache, package format and identity**: `internal/cache/`, `internal/unitypackage/`,
  `internal/model/`. Derives every path the tool writes and reads the descriptor that says
  which product a file is. What goes wrong here: a path that escapes the library root by
  spelling or through a symlink; an operation that acts on a joined path rather than
  through `os.Root`; a name that folds to an empty segment or a Windows device name; a
  relocation that overwrites; a removal that trusts the path it was handed; a descriptor
  reader that reports "no metadata" for a package that has some; a failure path that
  leaves an empty `<publisher>/<asset>/` behind.
- **Sync orchestration and the lockfile**: `internal/syncer/`, `internal/lockfile/`. Owns
  `classify`, the semantic download guards, the adoption gates, the bounded download pool,
  the per-asset `persist`, and the file a project commits. What goes wrong here: a class
  that resolves against the wrong entry; a guard that runs after the commit rather than
  before it; an advertised field leaking into the resolution half; a mutation in the
  classification pass that is never persisted; a concurrent lockfile write that loses the
  record it exists to keep; a cancellation counted as an asset failure.
- **CLI, config and the select page**: `main.go`, `main_test.go`, `audit_test.go`,
  `internal/config/`, `internal/web/`, `internal/manifest/`, `internal/humanize/`,
  `config.example.toml`, `unity-sync.example.toml`. Flag parsing, the precedence chain,
  exit codes, and the only surface that writes the manifest. What goes wrong here: a flag
  parsed after a positional and therefore ignored; a flag a subcommand accepts and never
  reads; a path the user named that does not exist and silently reads as "nothing
  configured"; an exit code that hides a failure; a select page that clobbers a curated
  manifest. The page is an `html/template` literal with inline CSS and JavaScript at
  `internal/web/web.go`; it is in scope, and so is the store-controlled data rendered into
  it. `internal/humanize` is three dozen lines and sits here because both its callers
  render for a person, but one of them formats inside a download goroutine, where a panic
  takes the whole run down rather than one asset.
- **Distribution and fixtures**: `internal/selfupdate/`, `internal/fixtures/`,
  `cmd/scrubfixtures/`, `install.sh`, `install_test.go`, `.github/`. Replaces the running
  binary and regenerates the test fixtures. What goes wrong here: an update that leaves no
  working binary behind; a GitHub credential sent to a host other than the API it was
  meant for, or put somewhere a process list can read it; a 404 for a version that was
  never tagged reported as a rejected credential; a scrub that lets through a field the
  pinned query never asked for; a release that ships without its gate; a CI guard that
  passes because it matched nothing. `install.sh` composes the asset label from `uname` in
  its own language, and `install_test.go` is what holds that composition to the labels
  `release.yml` actually publishes; the two are otherwise a contract nothing compiles
  together. `platformAsset` (`internal/selfupdate/selfupdate.go`) is the same contract in
  Go, pinned by `TestPlatformAssetNamesMatchWhatTheReleaseWorkflowPublishes`, so a platform
  added to the workflow has to reach two places or the updater cannot find its own asset.
  `.github/workflows/` is reviewed as code: it decides whether a build ships, and it runs
  beside `contents: write` and `id-token: write`.

For each sub-agent, provide:
- The full list of files in its area, not a diff.
- The scope description from the user, if any, so it knows what to focus on.
- The review criteria below that apply to its area, plus the core invariants,
  which apply everywhere.

Tell sub-agents to read entire files rather than scanning for patterns. Finding a real
issue requires the surrounding context. Where a package documents its own contract, hold
the code to that contract.

Every `internal/` package here opens with a package doc comment stating that contract, and
those comments are the local form of the invariants below.

### Priority tiers

Tier by consequence, not by category. The categories under each tier are examples, not the
definition.

**Tier 1 (must fix):** produces behavior a user or the data can observe as wrong, or
violates a core invariant. Bugs, races, corrupt or non-atomic writes, swallowed errors that
hide a failure, layer violations.

**Tier 2 (should fix):** correct today, but the next change in this area is likely to break
it, or a real invariant has no test. Significant duplication, resource leaks, API shapes
that invite misuse, meaningful refactors.

**Tier 3 (consider):** removes something concrete. If you cannot name what it removes,
leave it out.

### The finding gate

Every finding must name its failure scenario: the input, call sequence, or state that
produces the wrong outcome. "This could race" is not a finding. "Two concurrent writes both
read before either writes, so the second save clobbers the first" is.

A finding that cannot name a trigger is dropped, not downgraded. Report file and line, what
goes wrong, and a fix specific enough to act on.

### Review criteria

**Core invariants (hard rules, violations are Tier 1)**

These are the contracts the whole tool rests on. They are stated in `CLAUDE.md` ("Key
invariants") and `docs/design.md`, which is the authoritative record of measured store
behaviour, the identity rules, and the failure model. Read `docs/design.md` before judging
anything about enumeration, the lockfile, the cache layout, or the download guards.

1. **`LS` is the credential, and its absence is named before any request.** Not the
   NextAuth session token, which neither endpoint consults; the store answers a missing
   `LS` with an opaque 500 that reads like a server fault.
   *Violation shape:* a client built from a cookie header that was never checked for `LS`;
   a `cookies.txt` parser that treats `#HttpOnly_` rows as comments and so drops exactly the
   authenticating cookie; a curl-paste parser that unquotes one shell's form and not the
   others, or reads `-H 'cookie: …'` and not `-b '…'`; a `-b` value holding no `=` taken as
   the header; a host filter that accepts cookies from outside the `unity.com` family or
   rejects the host-only spelling; a browser scan that returns the first profile it could
   parse rather than the first that carries `LS`.
   *Check:* `credentialCookie` and `ResolveFrom` (`internal/session/session.go`),
   `curlArguments`, `ansiCEscape` and `cookieArgument` (same file), and `resolveBrowser`
   (`internal/session/browser.go`), which is the second place the assertion has to hold;
   trace every construction of `store.Client` back to them. Guard tests:
   `internal/session/audit_test.go`, `internal/session/browser_test.go`, `audit_test.go`.

2. **No client that talks to the Asset Store follows a redirect.** An unauthenticated
   download 302s to Unity's OAuth page, and a client that follows it writes a sign-in page
   into the cache under a `.unitypackage` name. `internal/selfupdate` is the deliberate
   exception: GitHub's release-asset API 302s to a signed CDN URL by design.
   *Violation shape:* an `http.Client` or `http.Transport` constructed in `internal/store`
   (or anywhere that reaches `assetstore.unity.com`) without
   `CheckRedirect: http.ErrUseLastResponse`; a 3xx from a store endpoint treated as
   anything but an expired session. `bootstrapOnce` (`internal/store/store.go`) is the one
   documented exception to that second half: its route answers 404 by design, so a non-2xx
   there is normal and a 3xx is not the expired-session signal it is everywhere else. It
   still must not follow the redirect, and a response that issues no `_csrf` is still a
   hard failure.
   *Check:* `grep -rn CheckRedirect --include='*.go' . | grep -v _test` should find
   exactly one, in `store.New`. The exception is pinned by
   `internal/selfupdate/audit_test.go`, which redirects for real.

3. **Downloads ask for `Accept-Encoding: identity`, and refuse any response
   `Content-Encoding` other than `identity`.** The endpoint honours gzip by gzipping the
   already-gzipped package, and Go will not decode an encoding the caller requested. An
   explicit `identity` is what a proxy or TLS-inspecting appliance sends back to say the
   body was not transformed, and refusing it fails every asset behind one.
   *Violation shape:* a request built without the header; a response path that keeps bytes
   before the `Content-Encoding` check runs; the check reduced to "non-empty", or widened
   to accept any coding other than `identity`.
   *Check:* `Fetch` (`internal/store/store.go`). Guard tests:
   `internal/store/store_test.go`, `TestAnIdentityContentEncodingIsNotAReEncode`
   (`internal/store/audit_test.go`).

4. **A download body carries a stall guard, the API calls carry a deadline, and a rejected
   response's drain is bounded.** A 23 GB package legitimately takes hours, so no
   whole-request timeout may be imposed on a download. What is bounded is *silence*:
   `stallGuard` resets on every read returning bytes and cancels the request when the
   window expires, reporting `ErrStalled` rather than the context cancellation underneath
   it. Without it a body that stops mid-transfer blocks the read forever, the attempt never
   returns, `retry.Do` never gets to open a fresh connection, and the pool slot is never
   given up. The guard rides only on the body `Fetch` hands back, so the `reject` path
   (which drains to return the connection to the pool) is bounded by `requestTimeout`
   instead; a captive portal answering 200 `text/html` and going quiet would otherwise
   wedge the run through the one door the guard is not on. `internal/selfupdate` has its
   own `stallGuard` for the release body, for the same reason.
   *Violation shape:* a `Fetch` that returns `resp.Body` unwrapped; a `Client.Timeout` or
   whole-request context on the download path; the guard made advisory by treating its
   error as an interrupt; a drain in `Fetch` with no `time.AfterFunc` bound; a per-call
   deadline removed from `searchOnce` or `bootstrapOnce`.
   *Check:* `stallGuard`, `newStallGuard`, `Fetch` and its `reject` closure
   (`internal/store/store.go`); `stallGuard` and `assetStallTimeout`
   (`internal/selfupdate/selfupdate.go`). Guard tests: `internal/store/audit_test.go`
   (`TestAStalledBodyFailsRatherThanBlockingForever`,
   `TestAStalledBodyOnARejectedResponseDoesNotBlockForever`,
   `TestAStalledApiResponseFailsTheCall`, `TestAStalledBootstrapFailsTheCall`, and
   `TestASlowButLiveBodyIsNotCutOff`, which keeps the guard honest).

5. **Every store call retries on the same terms, the bootstrap included; the mid-run
   re-bootstrap is single-shot.** The bootstrap is the first request a run makes, so a 5xx
   there would otherwise end the run before any work was done while the identical fault
   one call later gets a full schedule. A bootstrap route that answers *without* a token
   is not retried: that status is not retryable and proceeding guarantees `ErrCSRF`.
   *Violation shape:* `Bootstrap` calling `bootstrapOnce` outside `retry.Do`; a
   no-token response returned unmarked so it retries; `search` calling `Bootstrap` rather
   than `bootstrapOnce` for its CSRF recovery, which nests a full schedule inside each
   attempt; a failed re-bootstrap swallowed so the user sees only "csrf token mismatch".
   *Check:* `Bootstrap`, `bootstrapOnce` and `search` (`internal/store/store.go`). Guard
   tests: `TestATransientBootstrapFailureIsRetried`,
   `TestABootstrapRouteThatIssuesNoTokenIsNotRetried`,
   `TestAFailedReBootstrapStillReportsACSRFMismatch` (`internal/store/audit_test.go`).

6. **The select page is served only to a browser on this machine.** Each request's `Host`
   is checked against the bound address, before the render as well as before the save. The
   per-run token stops a blind cross-origin POST but not DNS rebinding, which the browser
   treats as same-origin by name. The bind address is refused unless it names one address
   (`checkLoopback` in `main.go`), and `localRequest` refuses an unspecified bound address
   itself rather than trusting `main` to have done so, because `Serve` takes any
   `net.Addr` and the `localhost` and loopback-literal tests are true of a request from
   anywhere.
   *Violation shape:* the check moved to the POST branch alone, so the owned-asset list and
   the token are still readable; the unspecified-address refusal removed from
   `localRequest`; a bind address the check cannot express, making the page unreachable;
   the refusal leaking asset names in its body.
   *Check:* `localRequest` and `ServeHTTP` (`internal/web/web.go`), `checkLoopback`
   (`main.go`). Guard tests: `internal/web/audit_test.go`
   (`TestAForeignHostIsRefusedBeforeAnythingIsRendered`,
   `TestAWildcardBindIsRefusedByTheCheckItself`); `audit_test.go`
   (`TestSelectRefusesAnAddressThatIsNotThisMachine`,
   `TestRunRefusesAWildcardSelectAddress`).

7. **`resolvedVersionId` is the diff key, not the advertised `version.id`, and an asset id
   has exactly one entry.** The advertised value refreshes every run; pairing a refreshed
   id with an unresolved entry's file would mark it current forever. The delivered id is
   recorded but never diffed on, because for some products advertised and delivered
   differ as a steady state. Two entries for one asset id are refused at load by the
   lockfile and by the manifest: a rename re-keys an entry, so a merge can leave both, and
   every lookup walks a map, so a run would pick between them at random.
   *Violation shape:* a `Changed` decision that compares anything other than
   `prior.ResolvedVersionID` against the advertised id; a write that sets
   `ResolvedVersionID` from a value the file was not fetched against; a carried-forward
   entry whose resolution half gets refreshed alongside its advertised half, or whose key
   is re-derived rather than carried; `checkUnique` or the manifest's duplicate check
   weakened, or an entry with no `assetId` skipped rather than refused.
   *Check:* `classify`, `build`, `indexByAssetID` and `priorEntry`
   (`internal/syncer/syncer.go`); the two halves of `lockfile.Entry` and `checkUnique`
   (`internal/lockfile/lockfile.go`); `Load` (`internal/manifest/manifest.go`).

8. **Nothing unverified reaches a real cache path, and the write gate is no weaker than the
   read gate.** `cache.Store` streams to a temp file beside the destination and does not
   rename; `Commit` renames, after the syncer's semantic guards pass; `Discard` removes. An
   interrupt in that window would otherwise strand a rejected body where the next run's
   adopt scan takes it for genuine. `Store` also refuses every path a later read would
   refuse: one `Canonical` will not resolve, and one that leaves the library through a
   symlink.
   *Violation shape:* any write to a resolved destination path outside `Commit` and
   `Relocate`; a guard in `syncer.download` that runs after `Commit`; an early return
   between `Store` and `Commit` that neither commits nor discards; a `Relocate` onto an
   occupied destination; `Store` creating or writing through anything but the `os.Root`
   it opened.
   *Check:* `Store`, `Commit`, `Discard`, `Relocate` (`internal/cache/cache.go`). Guard
   tests: `internal/cache/audit_test.go`
   (`TestStoreRefusesToWriteThroughASymlinkTheReadsWouldRefuse`);
   `internal/syncer/audit_test.go`.

9. **Confinement is the filesystem's, not the string's.** `Canonical` settles a spelling;
   a path whose every segment is an ordinary name still leaves the library when one of
   them is a symlink. Every operation that opens, creates, moves or removes goes through
   `os.Root`: `rooted` for a lockfile-supplied path, and an `os.OpenRoot` inside `Store`,
   `Commit`, `Discard`, `Relocate`, `Find` and `RemoveStale`. `resolve` stays lexical and
   is only for callers that want a name, not a file. `pruneEmptyParents` goes through the
   root, or walking up removes the user's link and leaves the directory it pointed at.
   `Scan` and `SweepTemps` walk `rt.FS()` rather than the path, because
   `filepath.WalkDir` stops at a `library_path` that is itself a symlink (a Windows
   junction included) and silently indexes nothing; a symlinked directory *inside* the
   library is still not descended.
   *Violation shape:* an `os.Remove`, `os.Rename`, `os.Open`, `os.Stat` or
   `filepath.WalkDir` in `internal/cache` over a joined library path; a `resolve` result
   handed to anything that acts on the file.
   *Check:* `grep -n 'os\.\(Remove\|Rename\|Open\b\|OpenFile\|Create\|MkdirAll\|Stat\|Lstat\|ReadDir\|Chmod\)\|filepath.WalkDir' internal/cache/cache.go | grep -v '^[0-9]*:\s*//'`
   should match only `os.MkdirAll(root, …)` in `Store`, which creates the library root
   itself. Guard tests: `internal/cache/audit_test.go`
   (`TestARecordedPathCannotReachOutsideTheLibraryThroughASymlink`,
   `TestPruningNeverRemovesALinkTheUserPut`, `TestASymlinkedLibraryRootIsStillWalked`,
   `TestTheWalkStillDoesNotDescendALinkInsideTheLibrary`,
   `TestAPackageThatIsItselfALinkOutOfTheLibraryIsNotIndexed`).

10. **Adoption clears three gates inside the scan's own selection, and never reaches the
    file that just failed verification.** The descriptor's product id must match, its
    version id must match what the store currently advertises, and the file must clear the
    same size floor a download must clear; adoption is the one route into the cache that
    skips the download guards. The version and floor gates go to `cache.Index.Find` as
    `FindOptions.Accept`, because `Find` prefers the copy at the derived path, and gates
    applied to what it hands back rejected that copy while an intact one elsewhere sat
    unexamined. `Prefer` and `Exclude` are named fields because they are both root-relative
    paths with opposite meanings. `Changed` asks a separate probe, `adoptableInPlace`,
    restricted to a copy already at the derived path, because two projects share one
    library and the new build can already be there; the restriction keeps `Relocate` a
    no-op on that path. A delisted asset whose bytes are in the library is adopted, not
    reported undownloadable, because a download can never make up the difference.
    *Violation shape:* a gate applied to `Find`'s result instead of inside `Accept`; an
    adopt path missing any of the three gates; an `excludeRel` not set on some path where a
    recorded file exists and failed its check; `adoptableInPlace` calling `adoptable`
    (which re-hashes under `--verify` and excludes the copy worth adopting) or accepting a
    candidate that would need to move; an exclusion that cannot be resolved treated as "no
    exclusion" rather than refusing every candidate.
    *Check:* the `adoptable` and `adoptableInPlace` closures, `classify` and `adopt`
    (`internal/syncer/syncer.go`); `FindOptions` and `Index.Find`
    (`internal/cache/cache.go`). The candidates come from one `cache.Scan` per run,
    memoized lazily in `Run` and taken after the temp sweep. Guard tests:
    `internal/syncer/audit_test.go` (`TestAChangedAssetAdoptsTheNewBuildAlreadyInPlace`,
    `TestADelistedAssetAlreadyInTheLibraryIsAdoptedNotReported`);
    `internal/cache/audit_test.go`.

11. **The size floor is asked before the descriptor guards, and its republish
    discriminator is a re-read of the product.** A received count below
    `advertised - min(4096, advertised/8)` fails that asset. The descriptor is the first
    ~350 bytes, so a transfer that dropped inside them does not parse as gzip at all, which
    the descriptor guard marks permanent while the identical fault later reaches the floor
    and is retried. The one legitimate cause of a short body is a republish mid-download,
    and the only sound test for that is asking the store again; keying on "delivered id
    differs from advertised id" would switch the floor off permanently for the products
    where they steadily differ.
    *Violation shape:* the `unitypackage.ReadFile` call moved above `belowFloor` in
    `download`; a floor comparison that uses a size the run did not get from enumeration; a
    republish check that compares ids from the same response instead of re-querying; a
    `Lookup` error treated as "republished" and so silently disabling the floor.
    *Check:* `download`, `belowFloor` and `republished` (`internal/syncer/syncer.go`), and
    `store.Lookup` (`internal/store/store.go`).

12. **A failed download fails its asset, not the run; a pulled asset does not make the run
    exit non-zero; unfinished and unrecorded work does.** One delisted or corrupt package
    must not stop a 75 GB mirror, and the pool cancels early only for an expired session.
    Assets a cancelled pool never reached, and ones interrupted mid-attempt, are
    `NotAttempted` rather than failures, so an expired session is not buried under a
    cancellation per remaining asset; they still exit non-zero. An asset whose bytes landed
    and whose lockfile entry did not is `Unrecorded`, a warning naming the asset rather than
    a failure of it, and it keeps the exit status non-zero on all three persisting paths
    (download, adoption, the relocation a rename forces).
    *Violation shape:* a `return` out of the download pool on a per-asset error; a
    `cancelPool()` for anything but `store.ErrExpiredSession`; `store.ErrNotDownloadable`
    counted as retryable; a `context.Canceled` from a cancelled pool counted as
    `Retryable`; a persisting path that warns on a failed `persist` without setting
    `Unrecorded`; `Report.Failed()` losing any of its three terms.
    *Check:* the pool and the tally loop in `Run`, `Report.Failed()`
    (`internal/syncer/syncer.go`), and `syncOrStatus` (`main.go`). Guard tests:
    `internal/syncer/audit_test.go` (`TestAnUnrecordedResolutionWarnsAndStillFailsTheRun`,

**Correctness**

Name the branch and the input, not the category. The logic below is what is actually easy
to get wrong here:

- `classify` (`internal/syncer/syncer.go`). Check each of the seven classes against its
  condition: the delisted branch (`Unchanged` for a verified mirrored copy, else `Adopted`
  if the scan finds one, else `Undownloadable`); the `!resolved` branch where `hasPrior` is
  what separates `DownloadNow` from `New`; the out-of-date branch that asks only
  `adoptableInPlace`; and the order of the `ResolvedVersionID` test against the `cacheOK`
  test. Tier 1 for any branch that resolves against the wrong entry. `Classes()` and
  `Class.String()` must both name every class (`String`'s default arm answers
  "unchanged"); `TestEveryClassIsListedAndNamed` holds that.
- `belowFloor`. The allowance is `min(4096, advertised/8)`, the comparison is
  strict, and `advertised <= 0` disables the floor. Confirm no caller applies it to a size
  that did not come from enumeration, and that both adopt probes apply the same floor the
  download path does.
- `republished`. Returns false on a lookup error or a miss, which keeps the floor
  on. Confirm that is what each caller wants and that a false here cannot be read as "not
  truncated".
- `memoize`. Under `--verify` each probe is a full re-hash, so a second call is not
  a repeat but a doubling of the cost of verifying the whole library. Confirm every probe
  that can run twice goes through it. Tier 2.
- The pool's tally loop in `Run`. A result can be both resolved and `Unrecorded`, which is
  why that count is not an arm of the switch; a `context.Canceled` is converted to
  `NotAttempted` only when `poolCtx` itself ended. Check both against a pool cancelled
  mid-download.
- `cache.Canonical` and `safeSegment` (`internal/cache/cache.go`). Every path that
  reaches the filesystem must pass through them, including the ones built from a lockfile
  entry. Tier 1 for any that does not.
- `cache.Index.Find` and `pruneEmptyParents`. Exclusions and the root arrive however the
  user spelled them, so both must be canonicalised before comparison; an exclusion that
  cannot be resolved refuses every candidate; the scan is a snapshot, so each candidate is
  re-stat'ed; pruning must stop at the root for every spelling of it. Every failure path in
  `Store`, `Commit` and `Relocate` that made directories must unwind them, or an empty
  `<publisher>/<asset>/` is left in the tree quarry walks on every run.
- `model.slugify` (`internal/model/model.go`). Folding, separator collapsing, and the
  empty result. Both callers have a fallback; verify the fallback is reachable for every
  input that folds away.
- `unitypackage.fromExtra` (`internal/unitypackage/unitypackage.go`). The subfield walk
  is driven by each subfield's own length and XLEN is a uint16, so a prefix-limited reader
  would report "no metadata" for a package that has some, downgrading the hard wrong-asset
  check into a tolerated warning. Check the bounds arithmetic on a truncated and a
  maximally long header. Tier 1.
- `store.Enumerate` (`internal/store/store.go`). Termination on the empty page, that
  `rawRows` counts raw rows rather than deduped assets, and that `total` is the first
  page's.
- `store.searchOnce` and the error mapping. The batch is a JSON array answered
  positionally; check the indexing, that only the empty-message 500 is read as an expired
  session, that `classify` marks a body verdict permanent only when the status is not
  retryable, and that each mapped error still matches the failure model table in
  `docs/design.md`.
- `retry.Retryable` (`internal/retry/retry.go`), `retry.Permanent`, `Do`, and `backoff`.
  Which statuses retry, that a wrapped permanent error still unwraps for `errors.Is`, and
  that the backoff respects context cancellation.
- `build` (`internal/syncer/syncer.go`). Every owned asset gets an entry whether or not it
  is selected; the advertised half refreshes; the resolution half and the entry's key
  carry forward together so key and path cannot drift apart; `Removed` is sorted so the
  summary is stable.
- `manifest.Reconcile` (`internal/manifest/manifest.go`), `UnknownIDs`, and
  `SetEnabled`. Selection keys on id, so verify no path matches on name.
- `curlArguments`, `ansiCEscape`, `digitRun`, `cookieArgument`, `isCurlPaste`,
  `fromCookiesTxt`, `hostMatches` (`internal/session/session.go`). Each quoting state, the
  ANSI-C escapes a Firefox paste actually carries, the cmd form's caret escapes, `-b`
  against `-B`, the `#HttpOnly_` prefix, and both cookie scopes. Guard tests:
  `TestTheCmdFormsEscapingIsUndoneExactly`, `TestEveryAnsiCEscapeFirefoxEmitsIsDecoded`,
  `TestACookieJarFilenameIsNotReadAsTheCredential` (`internal/session/audit_test.go`).
- `lz4Decompress` (`internal/session/mozlz4.go`). The tool's only hand-written binary
  parser, run over a file another program wrote. Check every bound: the token nibbles and
  the 255-continuation in `readLength`, the literal run against `len(src)`, the match
  offset against `len(dst)`, the byte-at-a-time copy that the overlapping-match case
  depends on, and both places the output length is compared against the header's declared

  `internal/session/fuzz_test.go` run in CI; a finding here should say what input they

- `storeCandidates`, `storesUnder`, `profileDirs`, `installDefaults`

  `resolutions` map and the lockfile write inside `persist` under `mu`, and `done[i]`
  indexed writes. The save is inside the lock deliberately: released first, two goroutines
  can reach the rename in the order opposite to how they built their snapshots. Any change
  that moves a write out from under `mu` is Tier 1.
- Values read inside pool goroutines that are written outside them (`priorPaths`,
  `priorByID`, `opts`): confirm every one is written only before the pool starts. `found`
  and `excludeRel` are captured by the adopt closures and must stay confined to the
  sequential classification loop.
- The `store.Client` is shared across the pool and re-bootstraps CSRF from inside a request,
  so the credential pair is written while other goroutines read it; `credentials` and
  `adoptCSRF` hold `mu` (`internal/store/store.go`). Guard test:
  `internal/store/audit_test.go`.
- `cancelPool` and the `poolCtx.Err()` check at goroutine entry: a cancellation must not
  turn an already-resolved asset into a failure, and must not leave a goroutine blocked on
  the semaphore.
- `web.Handler`, its `once` and `done` channel, and `serveHandler`'s two drains
  (`internal/web/web.go`): a second POST, a client disconnect, or an interrupt that lands
  while a handler is mid-save must not lose an accepted save, send twice, or leave
  `Serve` blocked. Guard tests: `TestASaveAlreadyAcceptedSurvivesAnInterrupt`,
  `TestASaveAcceptedWhileTheInterruptLandsIsStillReturned`,
  `TestAnInterruptWithNoSaveIsReportedAsTheInterrupt` (`internal/web/audit_test.go`).

**Write integrity**

- Every file this tool writes is one a user commits or depends on: `unity-sync.lock.json`,
  `unity-sync.toml`, the cached packages, and the binary itself. All four write to a temp
  beside the destination, `Sync` it, and rename, so a crash cannot publish bytes that never
  reached the disk. A write path here that renames without syncing first, or that leaves
  its temp behind on a failed rename, is Tier 2. Check `lockfile.Save`
  (`internal/lockfile/lockfile.go`), `manifest.Save`
  (`internal/manifest/manifest.go`), `cache.Store`/`Commit`
  (`internal/cache/cache.go`), and `selfupdate.replace`
  (`internal/selfupdate/selfupdate.go`).
- Both committed files are byte-stable for unchanged state: `encoding/json` sorts the
  lockfile's map keys, `Save` turns HTML escaping off so an `&` in a name is not rewritten,
  `Resolution` is embedded *last* in `lockfile.Entry` (an embedded struct's fields are
  emitted at its own index, so moving it shifts every key in every entry), and
  `manifest.Save` sorts entries by id. A serialization that varies run to run, or a change
  that reorders keys, produces a spurious diff of the whole committed file and is Tier 1.
  Guard tests: `TestSaveIsByteStableAcrossRuns`, `TestAssetNamesAreNotHtmlEscaped`
  (`internal/lockfile/lockfile_test.go`).
- `sizeBytes` is always the received count, never the advertised one, and there is no run
  timestamp in the lockfile; stamping one would dirty a committed file on every no-op run.
  A field that makes a no-op run produce a diff is Tier 1.
- Modes: `Commit`, `lockfile.Save` and `manifest.Save` all keep an existing destination's
  mode and default to 0644 rather than inheriting a temp's 0600. A write path that drops
  that is Tier 2.
- Deletions: a run removes a file only when it is replacing that same asset's own copy (see
  invariant 19). A de-owned asset is reported and left in place.

**Resource use at scale**

Packages here reach 23 GB and a library reaches 75 GB, so this is not hypothetical.

- Any `io.ReadAll`, `[]byte` accumulation, or `bytes.Buffer` on a path that can carry a
  package body is Tier 1. `store.Fetch` hands the body back unbuffered on purpose. The
  release archive in `selfupdate.downloadBinary` is buffered by design and bounded by
  `maxArchiveBytes`; the GraphQL payload is bounded by `io.LimitReader`.
- Hashing and verification: `cache.Verify` is the cheap path (existence, exact size,
  version stamp) and `VerifyDeep` re-hashes; confirm the expensive one runs only under
  `--verify` and only once per file per run.
- `cache.Scan` walks the library once per run and the syncer memoizes it lazily, so a
  run where nothing needs adopting never walks at all. Check that nothing reintroduces a
  per-asset walk, and that the scan is still taken after the temp sweep: a partial in the
  index is a candidate the guards never saw. A full read where a header parse would do is
  Tier 2.
- `indexByAssetID` is built once per run so the pool's per-save `build` is not a map walk
  per owned asset. A reintroduced per-lookup walk on that path is Tier 2.
- Response header timeout versus body timeout: a slow body is legitimate here, a server
  that never answers is not. Guard test: `internal/store/audit_test.go`.

**Paths and portability**

- `filepath` for anything touching disk, `path` only for URLs, globs matched against a slug
  (`selected` uses `path.Match` so a backslash means the same on Windows), and the
  slash-space cache paths `internal/cache` carries. A lockfile records `cachePath`, which is
  committed and read on another machine, so check the separator handling on every write
  and read of it.
- The config dir chain (`--config` › `$UNITY_SYNC_CONFIG_DIR` › `$XDG_CONFIG_HOME` ›
  `~/.config`) and the library default (`$XDG_DATA_HOME/unity-sync`) are documented in the
  README and `config.example.toml`; a change to either without a docs change is Tier 2.
  `ExpandHome` accepts either separator after the `~`, since `~\lib` is what Windows tab
  completion produces.
- The release builds Windows and macOS binaries (`.github/workflows/release.yml`), so a
  path assumption that only holds on a case-sensitive Unix filesystem is a real defect, not
  a hypothetical one.
- `geckoRootsFor` (`internal/session/browser.go`) is a `GOOS` switch over home-relative
  paths, and only the Zen layout was verified against a real install. Check that every
  branch joins through `filepath`, and that a browser missing from the list stays reachable
  by pointing `--session` at a profile directory.

**Secrets and account data**

- The cookie header is the user's live session. Trace every place it could be printed,
  logged, wrapped into an error message, or written to a file. Tier 1 for any.
- A Gecko session store is a wider credential store than the header it yields: it holds
  every host the browsing session touched. Anything that widens what leaves
  `fromSessionStore`, or that folds decoded bytes into an error, is Tier 1. Which file a
  profile search settled on is printed on purpose (`resolveSession` in `main.go`), because
  a run against the wrong signed-in account is otherwise silent; what that file contained
  is not.
- `install.sh` passes the GitHub token through a curl config on stdin rather than as an
  argument, because arguments are visible in a process list. Any change that puts a
  credential on a command line is Tier 1.
- `selfupdate.token` reads `GITHUB_TOKEN`/`GH_TOKEN`, falling back to `gh auth token`;
  check what it does when they are absent and that it never echoes them. Every call that
  reaches the network takes a `context.Context`, and `main.go` builds the signal context
  before it dispatches `update`, so a Ctrl-C during a long download is a cancellation
  rather than a kill.
- `replace` renames a temp beside the target over the target. Windows will not let a
  running image be replaced, so a failed rename there falls back to `replaceAside`, which
  renames the running binary out of the way and takes its name, restoring it if the second
  rename fails. Guard test: `internal/selfupdate/audit_test.go`.

**The select page**

`internal/web/web.go` is an `html/template` literal carrying the whole page: markup,
inline CSS, and three inline functions. Every row rendered into it is store-controlled
text.

- Contextual escaping is the only thing making that safe, so any value that reaches the
  page outside `html/template`'s knowledge is Tier 1: concatenation into the template
  source, or a field typed `template.HTML`, `template.URL`, or `template.JS`. `absoluteURL`
  repairs a protocol-relative URL and is not a scheme allowlist.
- `page.Execute` runs after the status line is committed, so its error cannot become an
  HTTP error; it is printed to stderr instead, because `template.Must` does not run the
  escape analysis and an ambiguous-context edit serves 200 with an empty body. Check what a
  partial render leaves on screen.
- The save guards (the Host check, the per-run token against a stale tab, the `sync.Once`
  that makes "accepts one save" true rather than assumed, and the would-empty refusal) are
  what stop a rebinding page, an old tab, a second tab, or an empty POST from rewriting a
  curated manifest. None may become advisory.
- `OpenBrowser` (`internal/web/web.go`) starts a process with a URL this program built.
  It is an exported variable so a test can stub it; confirm nothing caller-supplied
  reaches it unvalidated, that a failure to launch is never fatal, and that no test path
  can leave the real launcher installed for a suite that drives `Serve`.

**Duplication and extraction**

- Repeated blocks (5 or more lines, similar structure) across files that
  should be a shared helper. Tier 2.
- Ignore trivial similarity: both call the same stdlib helper, both have an
  error check. Only flag duplication where extracting it measurably reduces
  the bug surface or eases a likely change.

**Refactoring opportunities**

- Code that grew incrementally and would benefit from restructuring now that
  its shape is clear: a function doing three things that should be three; a
  type that accumulated responsibilities; data flow that got indirect when a
  simpler path exists. Tier 2.
- Every suggestion must name a concrete improvement. It **removes** something
  (an indirection, a duplicated pattern, a coordination point, a way for two
  things to get out of sync), **enables** something (makes X testable,
  unblocks a use case, lets a change land in one place instead of N), or
  **generalizes meaningfully** (one shape replaces N near-duplicate variants).
  "Same behavior, different shape" does not qualify, however elegant. If you
  cannot name what improved, leave it out.

**Test quality (assess each suite as a whole, not test by test)**

Go's standard `testing` package, table-driven where it helps, with `httptest` servers and
`t.TempDir()` throughout and no third-party assertion or mocking library. Packages that
pin failure models keep them in a separate `audit_test.go` beside `<pkg>_test.go`; each
such test carries a comment saying what going wrong would look like. A new invariant test
belongs in `audit_test.go` and should carry that comment too. Where what must hold is how
often or in what order something runs rather than its result, the package indirects the
call through a package variable a test can count (`scanLibrary`, `verifyDeep` and
`saveLockfile` in `internal/syncer`, `syncFile` in `internal/lockfile`); an ordering
invariant asserted only on outcomes is a weak test. `internal/session` inlines its payloads
in the test files instead of keeping them under `testdata/`, because `.gitignore` matches
`cookies.txt` and `*.curl` anywhere in the tree; do not propose moving them out.

- Significant production behavior with no test at all, especially the core
  invariants above and every branch of the logic named under Correctness.
  Tier 2.
- Clusters of overlapping tests that could consolidate into fewer, clearer
  cases. Tier 2.
- Tests asserting implementation details (internal call order, private
  fields) instead of observable behavior. They break on refactor for no
  value. Tier 2.
- Duplicated test setup or helpers that could be shared. Tier 2.
- Weak assertions (a count checked but not the values, the wrong field
  asserted). Tier 2 only where the weakness could mask a real bug.
- Do not suggest tests for trivial edge cases, for every possible nil input,
  or splitting working tests for purity. Fewer, stronger tests beat many
  fragile ones.

**Go idioms**

Only what `gofmt` and `go vet` do not already decide. Do not report anything either of them
would have caught, and do not report style.

- Sentinel errors compared with `errors.Is`/`errors.As`, never by string match, and every
  wrap that a caller unwraps through using `%w`. The pool's classification of
  `store.ErrExpiredSession` and `store.ErrNotDownloadable` depends on this.
- `context.Context` threaded through every call that can block on the network or read a
  whole package. No `context.Background()` or `context.TODO()` below `main` except
  `serveHandler`'s shutdown (`internal/web/web.go`), which deliberately does not inherit an
  already-cancelled context; no ignored `ctx.Err()`.
- Response bodies closed on every path including error paths; `store.drain`
  (`internal/store/store.go`) exists so a connection can be reused, so check it is
  called where that matters and not where the body is handed to a caller.
- `defer` inside a loop body that runs once per asset.
- Goroutines with a bounded lifetime: every `go` has a `WaitGroup` or a channel that
  closes, and no send survives an early return with no reader.
- Exported identifiers in `internal/` that no other package calls. Export is a claim about
  the contract, so an unused one is a wrong claim. Tier 3.
- Two adjacent parameters of the same underlying type with different meanings, which
  compile either way round: this repo has turned four such pairs into distinct types or an
  options struct (`store.Credential`, `session.Resolved`, `cache.FindOptions`,
  `selfupdate.Requested`). A new one on a path that carries a credential or decides a
  delete is Tier 2.
- Keyed struct literals for types that gain fields, particularly `lockfile.Entry`,
  `lockfile.Resolution` and `model.Asset`.

**Cross-boundary consistency (flag here, synthesized in Step 4)**

When reviewing an area, note any exported API that looks easy to misuse
(parameter order, unclear units, implicit preconditions) and any call into
another area that assumes something about what it returns. These are inputs
for the cross-cutting analysis, which no single area agent can do.

## Step 4: Cross-cutting analysis

After the area agents report, trace each core invariant end to end across
boundaries, which no single agent could do:

1. **Session to request.** `session.ResolveFrom` (`internal/session/session.go`) →
   `resolveSession` (`main.go`) → `store.Credential` → `store.New`, `credentials` and

   arm and `resolveBrowser` (`internal/session/browser.go`). Confirm no path reaches a

   becomes a `store.Credential` at the one conversion and is a bare string nowhere else,

## Step 5: Verify and widen

For every finding from an area agent or from the cross-cutting analysis:

1. **Verify it yourself.** Read the file and line. Confirm the trigger is
   real. Drop anything speculative, cosmetic, or already handled elsewhere.
2. **Widen it.** Grep or glob for the same pattern across the whole
   codebase and report every occurrence, not just the one an agent happened
   to open.
3. **Mechanize what widens.** If a class has many instances and a tool could
   decide it, report one automation proposal instead of N findings: enable the
   lint rule, add the check, add a guard test. Check the lint configuration
   first, since a rule that exists but is disabled or not wired into CI is
   the cheapest fix available.
4. **Drop non-actionable observations.** Anything amounting to "noting this
   but it is fine" comes out.
5. **Deduplicate.** Merge findings that different agents reached from
   different angles into one item.

On step 3 in this repo: there is no linter configuration, so "enable the rule" is never
available as a cheap fix. An automation proposal here means a new `audit_test.go` guard
test in the owning package, a check added to `.github/workflows/ci.yml` (which already
carries two shell guards and a fuzz step), or introducing a linter for a specific named
check that would subsume a counted set of findings. Say which, and say how many findings it
subsumes. A guard test is usually the right answer, because the guard tests are where this
repo already records its failure models. A proposed CI guard must fail when it matches
nothing, the way the existing two do.

## Step 6: Report

Present the report and stop. Do not fix anything, do not write findings to
memory, and do not leave a findings file behind: the human triages in the
session, and saved findings become confidently wrong context later.

Organize by tier, then by category within a tier. Within a tier, order by
value against effort.

Each finding gets:
- File path and line numbers
- The failure scenario: what goes wrong and what triggers it
- A fix specific enough to act on
- One entry per pattern, with all occurrences grouped under it

**Test quality findings** are a cohesive assessment per area, not a list of
files. "The syncer tests cover classify and dedup well but nothing exercises
the expired-session abort" beats "syncer_test.go:42: missing test".

**Refactor findings** include a sketch of the target structure, or at minimum
name the functions and types that would result.

**Automation proposals** name the rule or check, the config file it goes in,
and roughly how many current findings it subsumes.

An area with no findings says so. A short report on sound code is a successful
audit, not a lazy one. No nits, no cosmetic notes, no "just flagging this".
